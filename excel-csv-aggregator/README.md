# CSV 集計ツール（Excel VBA）

フォルダに入れた売上・注文の CSV を、マクロ 1 回で **「年月 × 商品」の集計表** にする Excel VBA です。Shift_JIS と UTF-8 のファイルが混ざっていても、列の順番がファイルごとに違っていても読めます。期間が重なる CSV を入れても、同じ行を二重に数えません（例外は「9. 制限事項」）。

> 自主制作物です。実際の業務で使われたシステムではありません。
> **VBA のコードは、まだ Excel で一度も実行していません。** 集計のルールは Node.js の参照実装とテストで確かめています（「9. 制限事項と動作確認の状況」）。

Windows のデスクトップ版 Excel 専用です（Mac 版 Excel では動きません）。

## 1. 何をするツールか
1. 指定したフォルダの `.csv` をすべて読む（元のファイルは読むだけで、書き換えない）
2. 文字コード（Shift_JIS / UTF-8 / UTF-8 の BOM あり）を自動で判定する
3. 見出し名で「注文日・商品名・数量・金額・注文番号」の列を探し、決まった形の明細にそろえる
4. 複数の CSV に同じ行があれば 1 回だけ数える
5. 新しいブックに「集計」「月別合計」「明細」「取り込み結果」の 4 シートを作る

## 2. 解決する課題
- 管理画面からダウンロードした CSV を毎回開き、1 枚のシートに貼り付け、列を消して並べ替え、ピボットテーブルで集計している
- 期間が重なる CSV を落とすと、同じ注文が二重に入る。気づかないまま売上が多く見える
- Excel で CSV を開くと、UTF-8 のファイルが文字化けする、「0012」のような商品コードが 12 になる

## 3. 主な機能
| 機能 | 内容 |
|---|---|
| フォルダ内の CSV をまとめて読む | `.csv` だけを、ファイル名の文字コード順に読む（大文字が小文字より先、`10` が `9` より先。エクスプローラーの並びとは違う）。`~$` で始まる一時ファイルやサブフォルダは読まない |
| 文字コードの自動判定 | 先頭の BOM → UTF-8 として正しいか → Shift_JIS の順で判定。設定で固定もできる |
| 列を見出し名で探す | 列の順番違い・余分な列があってもよい。見出し名は「設定」シートで変えられる |
| 重複の削除 | 同じ行が複数の CSV にあるときは、ファイルごとの件数のうち最大の数だけ残す。1 つの CSV の中で同じ内容の行が 2 つあっても（同じ注文で同じ商品を 2 行に分けた場合など）消さない。注文番号の列がない CSV では注意が必要（「9. 制限事項」） |
| 集計 | 年月 × 商品（数量・金額）と、年月ごとの合計 |
| 入力チェック | 日付・数量・金額が読めない行、必要な列がない CSV、閉じていない引用符（`"`）、余分な引用符（`"`）で複数の行が 1 つの値に入ったように見える箇所、UTF-16 のファイルがあれば、集計を作らずにファイル名と行番号の一覧を出す（余分な引用符はすべての形を捕まえられるわけではありません。「9. 制限事項」）。どの CSV にもデータの行がなければ、そのことを知らせて集計を作らない |
| 値の読み取り | 「1,960」「¥1,960」「１９６０」「-980」（返品）、日付は「2026/9/1」「2026-09-01 10:30」「20260901」「2026年9月1日」などを読む |

## 4. 使用技術
- Excel VBA（Windows 版 Excel。参照設定は不要。`ADODB.Stream` と `Scripting.FileSystemObject` を使う）
- 参照実装とテスト: Node.js 標準のテストランナー（`node:test`）。外部ライブラリなし
- CI: GitHub Actions（テスト、gitleaks による秘密情報スキャン）

### ファイル
| ファイル | 中身 |
|---|---|
| `dist/CsvAggregator.bas` | **Excel に取り込むのはこちら**（Shift_JIS・CRLF。`npm run build` で生成） |
| `src/CsvAggregator.bas` | VBA の元のソース（UTF-8。GitHub で読めるように） |
| `src/lib.js` | 参照実装。VBA の関数と同じ名前・同じ手順 |
| `tests/cases/` | 共通テストケース（入力 CSV と、手で計算した期待値）。VBA の確認にも使う |

`.xlsm` は Git に入れていません。バイナリで差分が見えないことと、インターネットから取得したマクロ入りファイルは Office が既定でブロックするためです。

## 5. セットアップ方法
1. このリポジトリを ZIP でダウンロードして展開する（GitHub の「Code → Download ZIP」）。
2. Excel で新しいブックを作り、`Alt + F11` で VBA エディターを開く。
3. 「ファイル → ファイルのインポート」で `dist/CsvAggregator.bas` を選ぶ（`src/` のほうは UTF-8 なので文字化けします）。
4. 「デバッグ → VBAProject のコンパイル」を実行し、エラーが出ないことを確かめる。
5. ブックを「Excel マクロ有効ブック（*.xlsm）」として保存する。
6. `Alt + F8` → `SetupSettings` を実行すると、「設定」シートができる。

### ボタンで実行したい場合（任意）
「開発」タブ → 挿入 → ボタン（フォーム コントロール）を置き、マクロ `RunAggregation` を登録します。

## 6. 実行方法
1. 「設定」シートの黄色いセルを確認する。

   | キー | 初期値 | 説明 |
   |---|---|---|
   | CSV_FOLDER | （空） | CSV を入れたフォルダ。`C:\` などから始まる絶対パスで書く。エクスプローラーの「パスのコピー」で付く前後の `"` はそのままでよい。空なら実行時に選ぶ画面が出る |
   | ENCODING | 自動 | 自動 / UTF-8 / Shift_JIS。文字化けしたときだけ変える |
   | COL_DATE | 注文日 | 日付の列の見出し名 |
   | COL_PRODUCT | 商品名 | 商品の列の見出し名 |
   | COL_QUANTITY | 数量 | 数量の列の見出し名 |
   | COL_AMOUNT | 金額 | 金額の列の見出し名 |
   | COL_ORDER_ID | 注文番号 | 注文番号の列の見出し名。CSV にない場合は空にする（空にすると、別のファイルにある同じ内容の行は 1 行にまとめます。「9. 制限事項」） |
   | DEDUPE | TRUE | FALSE にすると重複を削除しない |
   | QUOTE_CHECK | TRUE | 引用符（`"`）で囲んだ複数行の値の中に、1 行分以上のデータに見える数のカンマがあればエラーにする。備考などに本当にカンマの多い複数行の文があってエラーになるときだけ FALSE にし、その回の集計が終わったら TRUE に戻す（FALSE のままにすると、次の月の CSV でもこの検査をしません）。空にしたとき、キーの行がないとき（前の版で作った「設定」シート）は TRUE として動く |

   前の版で作った「設定」シートでは、`SetupSettings` を実行し直しても、すでにある行の説明は書き換わりません（COL_ORDER_ID の説明は古いまま。動きは同じです）。
2. `Alt + F8` → `RunAggregation` を実行する。
3. 新しいブックができる。保存はされていないので、必要なら名前を付けて保存する。実行しても元の CSV と「設定」シートは変わらず、毎回新しいブックができます。
4. 「エラー」シートが出たときは、書かれたファイルと行を直してから、もう一度実行する。CSV はメモ帳などのテキストエディターで直してください。Excel で開いて上書き保存すると、「0012」が 12 に、「2026-10」が日付に変わったままファイルに残ります。出力元のデータを直して CSV を出し直せるなら、そのほうが確実です。

## 7. 使用例
`tests/cases/01-basic/input/` の 4 つの CSV（Shift_JIS・UTF-8 BOM あり・UTF-8 BOM なしの LF 改行と CRLF 改行。ダミーデータ）を集計すると、「月別合計」は次のようになります（期待値: `tests/cases/01-basic/expected/monthly.csv`）。

| 年月 | 数量 | 金額 |
|---|---|---|
| 2026-08 | 6 | 8,660 |
| 2026-09 | 8 | 10,620 |
| 2026-10 | 1 | -380 |
| 合計 | 15 | 18,900 |

9 月の注文 `A-1012` と `A-1013` はそれぞれ 2 つの CSV に入っていますが、1 回だけ数えます（「取り込み結果」シートの「重複で除いた行」が `c_2026-09-to-10.csv` と `d_2026-09-crlf.csv` で 1 ずつ）。`A-1013` の商品名は引用符の中に改行があり、改行コードの違うファイル（LF と CRLF）でも同じ商品として扱います。

## 8. 制作時に工夫した点
- **元の CSV を開かない**: `Workbooks.Open` で CSV を開くと、Excel が「0012」を 12 に、「2026-10」を日付に変えてしまう。ファイルをバイト列で読み、自前で分解する。出力でもセルを先に文字列の書式にしてから書き込む。
- **`Line Input` を使わない**: LF だけの改行や、引用符の中の改行で行がずれるため。CRLF・LF・CR のどれでも読めるようにした。引用符の中の改行は LF（Excel のセル内改行と同じ）にそろえ、改行コードの違うファイル同士で同じ値が別物にならないようにした。引用符が閉じないままファイルが終わったときは、後ろの行が黙って消えないよう、引用符が始まった行番号つきのエラーにする。余分な引用符が 2 つあって間の行が 1 つの値に入った場合も、閉じた引用符のすぐ後ろに文字が続く形と、値の中のカンマが 1 行分以上ある形はエラーにする。
- **重複の削除で、1 つの CSV の中の売上を消さない**: 「注文番号＋商品」で重複とみなすと、同じ注文で同じ商品を 2 行に分けたデータが消える。「ファイルごとの件数の最大を残す」ルールにして、1 つの CSV の中にある同じ内容の行は残すようにした。ただし、別々の CSV にある同じ内容の行は 1 行にまとめるため、注文番号の列がない CSV では正しい売上が減ることがある（「9. 制限事項」）。
- **VBA を CI で試せない問題への対策**: 集計のルールを Node.js の参照実装で書き、同じテストケース（入力 CSV と手で計算した期待値）を VBA の確認でも使う。VBA のソースは、ファイルを変える呼び出しがないこと、参照実装と同じ関数がそろっていることなどを静的にチェックする。
- **取り込み用ファイルの文字化け対策**: VBA エディターは `.bas` を Shift_JIS として読むため（二次情報。下の未確認を参照）、UTF-8 のソースから Shift_JIS 版を生成する。Shift_JIS にできない文字（半角の `¥` など）があればビルドで止める。

### 制限事項
- 商品名の表記ゆれ（全角・半角、途中の空白の違い）は、別の商品として集計します。引用符の中に改行を含む商品名も、改行のない同じ名前とは別の商品になります。
- 引用符の前に空白がある値（`, "a,b"` のように `,` と `"` の間に空白があるもの）は、引用符で囲んだ値として扱いません。中の `,` で列が分かれるため、列がずれることがあります。ずれた値は日付・数量・金額のチェックでエラーになることが多いものの、集計に使わない列の中だけでずれた場合は、エラーにならずに集計されることがあります（参照実装でもテストしていません）。
- **同じ注文が Shift_JIS の CSV と UTF-8 の CSV の両方にあり、その値に `〜`・`−`・`‖`・`¢`・`£`・`¬`・`＼` が入っていると、文字コードによって別の文字になり、重複として除かれずに二重に数えます。** エラーにはならず、「取り込み結果」の「重複で除いた行」にも出ません。同じ期間の CSV は、出力元で文字コードをそろえて（すべて Shift_JIS か、すべて UTF-8 で）落としてください。
- 金額は CSV の値をそのまま足します（税計算や端数処理はしません）。
- サブフォルダの CSV、Excel ファイル（.xlsx）、タブ区切りのファイルは読みません。
- 明細が 1,048,575 行（Excel のシートの上限から見出しの 1 行を引いた数）を超えるとエラーにします。これはシートの上限で、そこまで動くことを保証するものではありません。実際に何行まで扱えるか（メモリの制約。特に 32 ビット版の Excel）と、大きなファイルでの処理時間は未計測です。
- **注文番号の列がない CSV では、同じ日・同じ商品・同じ数量・同じ金額の行が、別ファイルにあると 1 行にまとめられます。** 重複の判定は日付（時刻は使わない）・注文番号・商品・数量・金額で行うためです。1 日分を午前と午後のように複数のファイルに分けて出力している場合は、DEDUPE を FALSE にしてください（期間が重なるファイルを入れないよう注意が必要です）。
- UTF-16 の CSV（Excel の「Unicode テキスト」で保存したものなど）は読めません。「UTF-16 には対応していません」というエラーにします。UTF-8 か Shift_JIS で保存し直してください。
- 次の形はエラーになります（黙って間違えることはありません）: 見出しの前にタイトル行がある CSV（「売上明細 2026年9月」など）、`▲980`・`△980` のような負数の書き方、日付と時刻の間が全角スペースの日付。
- CSV_FOLDER に相対パスを書くと、ブックの場所ではなく Excel の現在のフォルダから探します。絶対パスで書いてください。
- **値の先頭に余分な `"` が 2 つあると、間の行が 1 つの値に入ることがあります。** 多くの形はエラーにしますが（見出しの行で始まった場合も同じように調べます）、次の 3 つの形はエラーにならず、その行の売上が集計から消えます。
  1. 開いた `"` の行と閉じた `"` の行の間に、空の行か空白だけの行しかなく（すぐ次の行で閉じる場合を含む）、閉じた `"` の後ろが `,` で（間に空白があっても同じ）、閉じた列が開いた列より左にある場合。値の中のカンマが「見出しの列数 − 1」個に満たないので、1 行分のデータに見えません。例: 見出しが `注文日,商品名,数量,金額,備考` で、2 行目が `2026/09/01,商品A,1,100,"至急`、3 行目が `2026/09/02",商品B,1,200,` のとき、3 行目は 2 行目の備考に入ります。2 行目と 3 行目の間に空の行が 1 つ以上あっても、同じように 3 行目が消えます。見出しの行の備考で `"` が始まった場合も同じで、2 行目の売上が消えます。
  2. 出力元が後ろの空の列を省いていて、行ごとに列の数が違う CSV。入ってしまった行のカンマが少なく、1 行分のデータに見えないことがあります。
  3. QUOTE_CHECK を FALSE にしたとき。閉じた `"` のすぐ後ろに文字が続く形以外は、エラーになりません。
- 逆に、備考などに本当にカンマの多い複数行の文があると、行が消えていないのにエラーになることがあります（値全体のカンマが「見出しの列数 − 1」個以上のとき）。エラーの文に QUOTE_CHECK の切り方を書いています。

#### 行が消えていないかの確かめ方
余分な引用符が心配なときは、次の手順で確かめられます。

1. 「取り込み結果」シートで、そのファイルの「データ行」の数を見ます。
2. CSV をメモ帳で開き、Ctrl+End で最後へ移動して、画面の下の「行」の数字を見ます。ファイルが改行で終わっていると最後の行が空になるので、そのときは 1 を引きます。
   - 画面の下に数字が出ていなければ、メモ帳の「表示」→「ステータス バー」をオンにします。
   - 「ステータス バー」が灰色で選べないときは、先に「書式」→「右端で折り返す」をオフにします（以前のメモ帳の動き。この環境では確かめていません）。
3. 2 の数から、見出しの 1 行と、空の行の数を引きます。
   - 備考などの値の中で改行していないファイルなら、これで終わりです。1 の「データ行」と同じなら、行は消えていません。
   - 値の中で改行しているファイルでは、さらにその改行の数を引きます。数が多くて数えにくいときは、この手順ではなく 5 の方法を使ってください。
   - 1 の「データ行」と違うときは、その付近の行に余分な `"` がないかを見てください。
4. CSV を Excel で開いて行の数を数えても、確かめにはならないと考えられます。Excel も同じように、余分な `"` の間の行を 1 つのセルにまとめて読むためです（仮説。Excel では確かめていません）。
5. 入ってしまった値が「商品名」「注文番号」の列なら、「明細」シートのそのセルの中に改行があります。「明細」シートで Ctrl+F を押し、「検索する文字列」の欄で Ctrl+J（改行を入れる操作）を押して「すべて検索」すると、セルの中に改行がある行の一覧が出ます。改行のある商品名が、本当にそういう名前かを確かめてください。備考など「明細」に出さない列に入った場合は、この方法では見つかりません（Ctrl+J で改行を検索する操作は、この環境では確かめていません）。

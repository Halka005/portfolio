# 問い合わせ・ヒアリング受付 自動化ツール（GAS）

Google フォームに問い合わせが届いたら、**受付番号の発行・自動返信・担当者への通知・対応状況の管理**までを自動で行う Google Apps Script です。

> 自主制作物です。実際の業務で使われたシステムではありません。

<!-- スクリーンショットは Google 環境での動作確認後に docs/images/ に追加する -->

## 1. 何をするツールか
フォームの回答が届いた瞬間に、次の処理を自動で行います。

1. 回答に受付番号（例: `INQ-20261013-001`）をつける
2. 問い合わせた人へ、受付番号入りの自動返信メールを送る
3. 担当者へ、回答内容をまとめた通知メールを送る
4. 回答シートに「受付番号・ステータス（未対応）・処理日時」を書き込む
5. すべての処理を「ログ」シートに記録する

## 2. 解決する課題
- 問い合わせに気づくのが遅れる／返信を忘れる
- 「どの問い合わせに対応済みか」がわからなくなる
- 自動返信の文面を変えるたびにコードを直す必要がある

メール文面や通知先は**スプレッドシートの「設定」シートで変更できる**ため、コードを触れない担当者でも運用できます。

## 3. 主な機能
| 機能 | 内容 |
|---|---|
| 受付番号の自動発行 | 日付ごとの連番。手で番号を振る必要がない |
| 自動返信メール | 件名・本文はテンプレート。`{{お名前}}` のように回答を差し込める |
| 担当者への通知 | 回答内容とスプレッドシートの URL を送る |
| ステータス管理 | 「未対応 / 対応中 / 完了 / 対応不要」のプルダウン |
| お試しモード（DRY_RUN） | メールを送らず、送る予定の内容をログに残す。初期値は ON |
| 二重送信の防止 | 処理済みの行は再実行してもスキップする。同時送信は LockService で順番に処理する |
| エラー通知 | 失敗時はログに記録し、担当者にメールで知らせる |

## 4. 使用技術
- Google Apps Script（V8 ランタイム）、Google スプレッドシート、Google フォーム、MailApp
- テスト: Node.js 標準のテストランナー（`node:test`）。外部ライブラリなし
- CI: GitHub Actions（テスト、gitleaks による秘密情報スキャン）
- 開発: clasp（任意）、Claude Code

### ファイル
| ファイル | 中身 |
|---|---|
| `src/lib.js` | 受付番号・テンプレートの差し込み・設定の読み方などの純粋関数（Google のサービスを使わない） |
| `src/main.js` | GAS の処理（メニュー、フォーム送信時の受付、メール、ログ） |
| `src/appsscript.json` | 権限（OAuth スコープ）とタイムゾーン |
| `src/selftest.js` | 自己テスト（開発用。**納品物には入れない**）。テスト用のスプレッドシートで、送信イベントを作って本番の処理に流し、結果をシートに書く（「9. 自己テスト」） |

## 5. セットアップ方法
### かんたんな方法（コピー＆貼り付け）
1. Google フォームを作り、「回答」タブからスプレッドシートを作成する。
   - 質問に「お名前」「メールアドレス」を含める（名前は設定で変更可）
2. スプレッドシートの「拡張機能 → Apps Script」を開く。
3. 最初からある `コード.gs` の名前を `main` に変え、中身を `src/main.js` に置き換える。「＋」→「スクリプト」で `lib` を足し、`src/lib.js` の中身を貼り付ける。エディターではファイル名に `.gs` が付き、`main.gs`・`lib.gs` になりますが、それでかまいません。最後に保存する。ファイルの中身は、右クリック →「プログラムから開く」→「メモ帳」（Mac は「テキストエディット」）で開いてコピーする（Windows で `.js` をダブルクリックすると、開かずに実行しようとします）。
   - **貼る前に、エディタの中身を空にする**（右側をクリック → Ctrl+A → Delete）。最初からある `function myFunction() {` や、元の `appsscript.json` の中身が残ると、メニューが出ない・保存できないなどで動きません（2026-10-25 に実際に起きた）。貼ったあと、1 行目に `function myFunction` がないことを確かめる。
   - メニューが出ないときは、Apps Script の上の関数の選択で `onOpen` を選び「▷ 実行」を押すと出ます。ノートパソコンで F5 が音量などのキーになっている場合は、アドレス欄の左の ↻ か Ctrl+R で再読み込みします。
4. 「プロジェクトの設定」（歯車）で「「appsscript.json」マニフェスト ファイルをエディタで表示する」をオンにし、エディターに出た `appsscript.json` の中身を `src/appsscript.json` に置き換えて保存する（権限とタイムゾーンを本番と同じにするため）。
5. スプレッドシートを再読み込みすると、メニューに「受付ツール」が出る。

### clasp を使う方法
```bash
npm install -g @google/clasp
clasp login
cp .clasp.json.example .clasp.json   # scriptId を自分のものに書き換える（公開しない）
clasp push
```

## 6. 実行方法
1. メニュー「受付ツール → ① 初期設定」を実行する（初回は権限の承認が必要）。承認が終わったら、**もう一度同じメニューを押してください**（承認の直後は、押したメニューの処理が動かないことがあります。Google で未確認）。
2. 「設定」シートの黄色いセルを入力する。最低限 `NOTIFY_TO`（担当者のメールアドレス）。
3. メニュー「② 自動実行を有効にする」を実行する。
4. フォームからテスト送信し、「ログ」シートに `[DRY_RUN] 送信予定` が出ることを確認する。
5. 問題なければ `DRY_RUN` を `FALSE` にする。ここから実際にメールが送られる。

### 設定項目
| キー | 内容 |
|---|---|
| `DRY_RUN` | `TRUE` の間はメールを送らない |
| `EMAIL_FIELD` / `NAME_FIELD` | フォームのメールアドレス・名前の質問名（完全一致） |
| `NOTIFY_TO` | 担当者の通知先（カンマ区切りで複数可） |
| `SENDER_NAME` | 自動返信の差出人名 |
| `REPLY_SUBJECT` / `REPLY_BODY` | 自動返信の件名・本文 |
| `NOTIFY_SUBJECT` | 担当者向け通知の件名 |

テンプレートでは `{{質問名}}`、`{{受付番号}}`、`{{回答一覧}}` が使えます。

## 7. 使用例
フォームに「お名前: 山田 / メールアドレス: yamada@example.com / お問い合わせ内容: 見積もりがほしい」と送信されると、

- 山田さんに「【受付番号 INQ-20261013-001】お問い合わせを受け付けました」が届く
- 担当者に「【新規受付】INQ-20261013-001 山田 様」が届く
- 回答シートの行に `INQ-20261013-001 / 未対応 / 処理日時` が入る

## 8. 制作時に工夫した点
- **安全側に倒した初期設定**: 最初は DRY_RUN が ON。実際にメールが出るのは、依頼者が確認して OFF にしてから。
- **再実行しても壊れない**: 受付番号が入った行は処理済みとして扱い、二重送信しない。
- **列がずれても壊れない**: 管理用の列は位置ではなく見出し名で探す。フォームに質問を追加しても動く。
- **最小限の権限**: `appsscript.json` で、紐づいたスプレッドシートだけを扱う権限（`spreadsheets.currentonly`）とメール送信権限に絞っている。
- **テストできる構成**: Google に依存しない処理を `lib.js` に分け、単体テスト 11 件を用意。`main.js` の流れも GAS のモックで結合テスト 12 件を用意（`npm test`）。
- **設定はシートで**: 文面や通知先をコードの外に出し、引き継ぎやすくしている。

- 自己テストの限界: Google の上で送信の関数（`MailApp`）を差し替えられず、1 日に送れる残りの通数も読めないときは、送ったかを見張れないので、A02〜A05 は判定せずに未実施になる（○ にはしない）。
- 添付ファイル付きの回答や、Slack・Chatwork への通知には未対応。

### 自己テスト（開発用。納品物には入れない）
Google の上での動作確認を、メニューを押すだけで済むようにしたものです。テスト用のスプレッドシートに回答を 1 行ずつ足し、フォームの送信と同じ形のイベントを作って本番の受付の処理に流し、結果を「自己テスト」シートに項目ごとの ○ / × / 未実施で書きます。**Google ではまだ一度も動かしていません**（モックの上のテストだけ）。

**パソコンのブラウザ（Chrome など）で作業してください。** スマホのアプリではメニュー「受付ツール」が出ない見込みです（未確認）。Apps Script のエディターも、パソコンのブラウザで使います。

| 番号 | 確かめること |
|---|---|
| A01 | 「設定」の初期値の DRY_RUN が TRUE（× なら A02〜A05 は流しません） |
| A02 | 1 件目（山田 太郎、`yamada@example.com`）。右端に「受付番号」「ステータス」「処理日時」の見出しが足され、受付番号が `INQ-（今日の日付）-001`、ステータスが「未対応」で 4 つの選択肢のプルダウン、処理日時が日付。ログに送信予定 2 行と完了の 1 行、ERROR なし |
| A03 | 2 件目。受付番号が `-002`（連番） |
| A04 | 1 件目の行でもう一度呼ぶ。「処理済みのためスキップしました」の 1 行だけで、受付番号は変わらず、送信予定も足されない |
| A05 | メールアドレスが `not-an-email`。自動返信は送らず（WARN）、担当者への通知の送信予定だけ。受付番号は `-003` |
| A06 | 「設定」シートを変えていない |

- **メールは送らない作りです。** 設定は自己テストの中で初期値から作り、DRY_RUN が TRUE のときだけ本番の処理を呼びます（DRY_RUN が TRUE でなければ、呼ばずに止めます）。宛先は `@example.com` のダミーだけです。本番の処理の中でエラーになったときの通知も、渡した設定（DRY_RUN = TRUE）で決まるので送りません。
- 本番の受付の処理が壊れていて DRY_RUN を守らなかった場合に備えて、自己テストは本番の処理を呼ぶ間だけ、メールを送る関数（`MailApp`）を「送らずに数えるだけ」の代わりに差し替え、終わったら必ず元に戻します。差し替えが効けば、本番が壊れていてもメールは送りません（例外: 本番のコードが `MailApp` を関数の外（最上位）で別の名前に控えるように壊れると、差し替えを素通りして送ります。今の `main.js` が `MailApp` を使うのは `sendMail_`・`notifyError_` の中だけであることを Node のテストで確かめています。素通りしても、残りの通数が減れば × にして止めます）。差し替えられたかは、「自己テスト」シートの I05 に「送信の関数=差し替えた（4 回とも）」「差し替えられない（…）」「呼んでいない」のどれかで出ます。本番の処理の例外が外まで出たときも、送ったかの判定を済ませてから × にします。送ろうとした（代わりが呼ばれた）項目は、ログの文に関係なく × にし、残りの A02〜A05 は流さずに未実施にします（Node のテストでのまね）。**GAS の上で `MailApp` を差し替えられるかは未確認です。**
- 差し替えが効かなかったときは、項目の詳細に「送信の関数を差し替えられませんでした」と出します。そのときは、本番の処理を呼ぶ前後で「1 日に送れる残りの通数」（`MailApp.getRemainingDailyQuota()`）を読み、減っていたら × にして残りを流しません（ログに「送信しました」が出たときも同じ）。この場合は、最初に送った項目の分だけ `@example.com` 宛てに送ります（Node のテストのまねでは 3 通まで）。**送ってすぐに残りの通数が減るかも未確認です。** 差し替えが効かず、残りの通数も読めないとき（送信を見張る手段が 1 つもないとき）は、A02〜A05 を ○ にせず、「送信を見張れないので判定しません」で未実施にし、残りも流しません。ただし、差し替えが効かず、残りの通数は読めてもすぐには減らないときは、ログの文だけが頼りになり、壊れ方によっては 5 通送っても「すべて合格」になりえます。そのため、作業 2 の最後に Gmail の「送信済み」を見ます。
- **自己テスト用のスプレッドシートに「設定」シートを作らないでください。** 「設定」シートがあると、A02〜A05 は流さずに未実施にし、理由の欄に「「設定」シートを消してから押してください」と出します（流すかどうかは、あるかだけで決めます）。本番の処理が壊れて「設定」を読むようになっても、エラーの通知を含めてメールの送り先がないようにするためです（Node のテストでのまね）。
- 期待の受付番号・ログの文・見出し・ステータスの選択肢は、自己テストのコードに文字で直接書いています（本番の関数で作ると、本番が間違っていても ○ になるため）。今日の日付の部分だけは、自己テストが別に作ります。
- 「設定」シートの値は、前後で同じかを比べる（A06）だけで、使わず、詳細にも書きません。書き込みもしません。フォームも要りません（回答は「自己テスト_回答」シートに自己テストが書きます）。「ログ」シートはなければ作り、あれば行を足します（消しません）。
- 実行の途中で日付が変わると、受付番号の日付が変わるので、A02〜A05 のうちまだ × が出ていない項目は未実施になります。すでに出た × は残し、詳細に「途中で日付が変わりました」と足します（日付のせいの × のこともあります）。最後の画面に「M01・M02 はまだ書かずに、もう一度押してください」と出るので、もう一度押してください。
- スプレッドシートの名前が「自己テスト」で始まらないと、何もせずに止まります（本番のデータを消さないため）。
- 全体の「すべて合格」は、**自動で確かめる項目だけ**が全部 ○ という意味です。本番のフォームとメニューからの実行（M01）と承認画面の文（M02）は含みません。
- 押すたびに「自己テスト」シートと「自己テスト_回答」シートを作り直し、最初から実施します（続きから実施する仕組みはありません。30 秒以内で終わる見込みで、未測定）。

      - ZIP の URL: https://github.com/Halka005/portfolio/archive/refs/heads/main.zip（GitHub の「Code」→「Download ZIP」と同じものです）
   2. 新しいスプレッドシートを作り、名前を「**自己テスト_受付**」にする。**このスプレッドシートに「設定」シートを作らない**（「① 初期設定」も押さない。「設定」があると A02〜A05 を流しません）。
   3. 「拡張機能」→「Apps Script」で、「5. セットアップ方法」の「かんたんな方法」と同じように `main.js`・`lib.js` を貼り、**`selftest.js` も**「＋」→「スクリプト」で `selftest` を足して貼る。手順 4 のとおり `appsscript.json` も `src/appsscript.json` に置き換える（本番と同じ権限で動くかを確かめるため）。ファイルの中身は、右クリック →「プログラムから開く」→「メモ帳」（Mac は「テキストエディット」）で開いてコピーする。「① 初期設定」は押さないでください（「設定」シートができるため）。
2. **自己テストを押す**: スプレッドシートを再読み込みし、メニュー「受付ツール」→「自己テスト（開発用）」。承認画面が出たら、**権限の文を書き写す（スクリーンショットでもよい）。あとで M02 に書きます**（承認したあとは、この画面はもう出ません）。画面に出る自分のメールアドレスと名前は書き写さないでください（スクリーンショットなら、その部分を塗りつぶす。アドレス欄と右上のアカウントのアイコンも写さない）。初めての承認で「このアプリは Google で確認されていません」と出たら、「詳細」→「（プロジェクト名）に移動」で進みます（自分で作ったスクリプトなので出る画面です）。承認したら、もう一度押す。終わると結果の 1 行が出て、「自己テスト」シートが開きます。
   - **押す前と終わったあとに、Gmail の検索欄に `in:sent example.com` と入れ、出た件数を見る**（「送信済み」のうち、example.com を含むメールが出ます。初めてなら 0 件のはずです）。**増えていなくても、作業 4 で送るときに「送信済み: 増えた／増えていない」を必ず書いてください。** 増えていたら、自己テストの結果に関係なく、増えた件数と件名も書いてください（自己テストが送信を見逃したことになります）。受信トレイに「届きませんでした」という知らせが来た場合も同じです。MailApp で送ったメールが「送信済み」に出るかは未確認です。
3. **本番の確認（M01）**: 自己テストの全体が「すべて合格」か「不合格」になってから、下の M01 の手順をする。
4. **書いて送る**: 「自己テスト」シートの M01・M02 の黄色のセル（E 列）に結果を書き込み、シートを送る（「ファイル」→「ダウンロード」→「カンマ区切り形式（.csv）」で現在のシート。スクリーンショットは、全部の行が写るときだけでかまいません。アドレス欄とアカウントのアイコンは写さない）。送るときの文に、作業 2 の「送信済み: 増えた／増えていない」を書く。

#### M01: 本番のフォームとメニューでの確認（必須）
自己テストは設定を引数で渡し、送信イベントも自分で作るので、本番の入口（本物のフォームの送信とトリガー、「設定」シートから DRY_RUN を読む経路）は通りません。別のスプレッドシートで 1 回だけ確かめます。

1. Google フォームを新しく作り、記述式の質問「お名前」「メールアドレス」「お問い合わせ内容」を作る（フォームの設定の「メールアドレスを収集する」は使わない）。
2. フォームの「回答」タブで、回答の送信先に新しいスプレッドシートを作り、名前を「**本番確認_受付**」にする（「自己テスト」で始めない）。
3. そのスプレッドシートに、**自己テストと同じ ZIP** から展開した `main.js`・`lib.js`・`appsscript.json` だけを貼る（**`selftest.js` は貼らない**）。
4. 再読み込みして、メニュー「受付ツール」に「自己テスト（開発用）」がないことを見る。
5. 「① 初期設定」を押す（承認がもう 1 回ある。承認画面の文を書き写す。メールアドレスと名前は書き写さない）。承認のあとはもう一度押す。
6. 「設定」の `NOTIFY_TO` に `notify@example.com` を入れる。**`DRY_RUN` は TRUE のまま**にする。
7. 「② 自動実行を有効にする」を押す。
8. フォームを公開し（「送信」→ リンク。公開しないと回答できない）、**回答者用の画面（viewform）** から 1 回送信する（プレビュー（目のマーク）からは送信できない。お名前「山田 太郎」、メールアドレス `yamada@example.com`、お問い合わせ内容は何でもよい）。**同じ日に 2 回送ってしまったら**（受付番号が `-002` になる）、フォームと「本番確認_受付」を作り直して、1 からやり直す。
9. 「自己テスト」シートの M01 の E 列に、次の 5 つを書く。
   1. メニューの項目（4 で見たもの）
   2. 回答の行に受付番号（`INQ-` で始まり `-001` で終わる）とステータス「未対応」が入ったか
   3. 「ログ」に `[DRY_RUN] 送信予定` が 2 行あり、ERROR がないか
   4. Gmail の「送信済み」に `example.com` 宛てが増えていないか（DRY_RUN が TRUE なので、増えていないのが期待どおり。宛先が example.com なので「届いたか」はオーナーには見えないため、「送信済み」で見る）
   5. ZIP をダウンロードした日
10. 終わったら、**フォームの公開をやめる**（「回答を受け付けない」にする）。「本番確認_受付」はメニュー「受付ツール」→「自動実行を停止する」を押すか、フォームとスプレッドシートを消してかまいません（DRY_RUN が TRUE なので、トリガーが残ってもメールは送りません）。

M02 の E 列には、承認画面の文（自己テストのときと M01 のとき）を書き写すか、スクリーンショットを添えてください。自分のメールアドレスと名前は書かないでください。スクリーンショットなら、その部分を塗りつぶし、アドレス欄とアカウントのアイコンは写さないでください（M01・M02 に書いたものは、そのまま送られます。自己テストは伏せません）。

- **M01・M02 は、自己テストの全体が「すべて合格」か「不合格」になってから書く。** 書いたあとにもう一度押すと、「M01・M02 に書き込みがあるので、止めました」で止まります（書いたものを消さないため）。押し直したいときは、書いたものを別に控えてから「自己テスト」シートを消して押してください。
- M03（任意の手で確認）の E 列には書かないでください。任意の確認は、下の行ごとに「何を見て、どうだったか」を別に送ってください。
  - DRY_RUN = FALSE にして、自分のアドレス宛てに 1 件送り、自動返信と通知が届くか（「本番確認_受付」でする。**「自己テスト_受付」ではしない**。`NOTIFY_TO` も自分のアドレスにする。終わったら DRY_RUN を TRUE に戻す）
  - 「② 自動実行を有効にする」を 2 回押しても、トリガー（Apps Script の左の「トリガー」）が 1 つだけか

#### 依頼者に納品するとき
- **`src/selftest.js` は入れない。** 貼らなければ、メニューにも動きにも自己テストは出ません（M01 で確かめます）。
- clasp で納品先に push する場合: このフォルダには `.claspignore` がないので、`rootDir` の `src` にある `selftest.js` も push されます。**`src/selftest.js` を `src` の外に移してから `clasp push`** し、終わったら戻してください。

#### 確認状況の表の直し方（結果を受け取った人）
- ○ の項目に対応する行を「確認済み（日付、自己テスト A04、ZIP の日付）」に直す。× と未実施の行は直さない。
- **1 つの行に番号が複数あるときは、その全部が ○ のときだけ確認済みにする。** 1 つでも × か未実施なら直さない。
- **本番の入口を含む行**（「実際の Google 環境での動作」「お試しモード（DRY_RUN）」「承認画面の文」）は、**自己テストの番号 ＋ M01（と M02）の両方がそろって初めて確認済み**にする。「M01 がそろう」は、M01 の E 列に書いた 5 つ（メニューの項目、受付番号とステータス、ログ、Gmail の「送信済み」、ZIP の日付）が、どれも M01 の手順 9 の期待どおりであること。1 つでも違うか書いていなければ、そろっていない。片方だけなら「一部確認（自己テスト A02・A03 は ○、本番のフォームとメニューは未確認）」と書く。
- A06 は、この表のどの行にも結び付けない（自己テストの安全の確認）。
- **作業 2 の最後に見た Gmail の「送信済み」で `example.com` 宛てが増えていたら、その回の結果ではどの行も直さない。** 「増えた／増えていない」の知らせがない回も、どの行も直さない（M01 (4) と同じく、書いていなければ確かめていないとみなす）。A02〜A05 の詳細に「送信の関数を差し替えられませんでした」か「送信を見張れないので判定しません」が出た回も、どの行も直さない（送ったかを確かめきれていないため）。
- M03 は、この表のどの行にも結び付けない。任意の確認の行（実際のメール送信、トリガーが 1 つだけ、承認の直後など）は、行ごとに「何を見て、どうだったか」をもらったときだけ確認済みにする。「全部 OK」のようなまとめた返事では直さない。
